# 行情定时刷新与失败重试

日期：2026-10-23。范围：基金净值与积存金参考报价的后台定时刷新、失败重试、批量刷新、运行日志和状态监控。提交：`b2bdb06`（本地功能分支，未推送）。

## 1. 背景

此前行情只能由用户在基金或积存金页面手动刷新，失败时不会自动重试，也没有统一的运行状态或批量刷新入口。产品要求行情保存有效日期、来源、取得时间和失败状态，定时任务不依赖浏览器打开（§14.1、§6.4、AC14）。

## 2. 刷新服务

新增 `QuoteRefreshService`，统一编排基金和积存金刷新：

- 可选择 `all`、`funds` 或 `gold` 范围。
- 基金逐个调用现有 `FundService.RefreshQuoteAsync`；积存金调用 `GoldService.RefreshQuoteAsync`，没有积存金持仓时不创建空持仓。
- 单次失败不会阻断其他基金；每只基金独立记录结果。
- 只对 `Unavailable` / `Conflict` 重试，`Invalid`（例如缺少基金代码）和 `NotFound` 不重试。
- 重试次数最多再增加 5 次；每次重试写入 Warning 日志，最终结果写入 Information / Warning 日志。
- 同一时间只允许一个刷新任务；手动刷新和定时任务重叠时，后启动的请求返回 409 或跳过。
- 行情未变化时沿用现有逻辑，不重复生成行情观测或资产交易。

配置节 `QuoteRefreshScheduler`：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `Enabled` | `true` | 是否启用后台定时刷新 |
| `IntervalSeconds` | `900` | 检查间隔，最少 5 秒 |
| `RunOnStartup` | `false` | 启动时是否立即刷新 |
| `RetryCount` | `1` | 首次失败后的重试次数（0 至 5） |
| `RetryDelaySeconds` | `3` | 两次尝试之间的等待 |
| `IncludeFunds` / `IncludeGold` | `true` | 定时任务包含的资产；两者都关闭时任务不执行 |

定时任务使用 `PeriodicTimer`，每次运行后重新计算下次时间；不依赖浏览器或前端定时器。生产默认每 15 分钟检查一次。

## 3. 接口与监控

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ledger/quotes/status` | 定时任务开关、间隔、下次运行时间、最近一次运行、每个基金 / 积存金的最近报价、来源、有效日期、尝试时间、失败原因和状态 |
| POST | `/api/ledger/quotes/refresh` | 批量刷新；请求体 `{ "scope": "all" \| "funds" \| "gold" }`；返回每项成功 / 失败、尝试次数、是否更新、来源、价格、有效日期和错误 |

状态值：

- `fresh`：最近一次刷新成功，且报价日期在 7 天内。
- `stale`：最近一次刷新成功，但报价日期超过 7 天。
- `failed`：最近一次尝试失败，保留最近有效价格和日期。
- `never`：尚未自动刷新。
- `missingCode`：基金缺少代码，无法请求行情。
- `notRecorded`：尚未录入积存金。

`QuoteRefreshMonitor` 以单例保存最近一次运行和当前是否正在刷新；“我的 → 行情更新状态”展示定时任务状态、最近运行明细（每个标的的尝试次数和是否更新）、刷新按钮和各持仓状态。

## 4. 前端

- 新增 `/quotes` 行情更新状态页：
  - 显示定时刷新开关、间隔、下次运行和检查时间。
  - 提供“刷新全部 / 刷新基金 / 刷新参考金价”三个批量入口。
  - 展示最近一次运行的基金 / 积存金成功数、更新数、耗时、每次尝试次数和错误。
  - 每个基金 / 积存金显示当前价格、有效日期、上次尝试、来源、失败原因和状态标签。
- “我的”增加“行情更新状态”入口。
- 定时刷新或手动刷新失败时，页面继续显示最近有效值并明确“刷新失败”，不写 0 或推算值。

## 5. 验证

- 后端新增 7 项测试：
  - 5 项批量刷新服务测试：首次失败后重试成功并写入 monitor；连续失败按配置停止并保留错误；单只失败不阻断其他基金、缺少代码标记；积存金重试；状态反映定时配置和无积存金持仓。
  - 2 项 API 测试：无持仓时状态 / 批量刷新返回 0 项并记录手动触发；未初始化账本刷新返回 404。
- 后端完整 234 项在真实 PostgreSQL 下全部通过（含 17 项数据库测试）；前端 75 项、类型检查和生产构建通过。
- 浏览器验收：使用独立临时库、5071 / 5175 实例和本地行情桩。桩让基金前两次请求返回 500，第三次成功；积存金首次成功。启动时定时任务自动执行，基金尝试 3 次后成功，积存金 1 次成功；运行日志包含两次“第 N/3 次刷新失败，将重试”和最终完成日志。手动“刷新全部”成功，更新 0 项（行情未变化）。停止行情桩后，定时任务按 3 次尝试失败，页面显示“刷新失败”、保留 12.3456 和 910.50 及有效日期；恢复行情桩后手动刷新恢复为“已更新”。行情桩共收到数十次请求，但备份中仍只有 2 条基金行情和 2 条积存金行情（各含起始记录），未重复生成。

## 6. 边界

- 运行状态和最近一次结果保存在进程内，服务重启后清空；完整历史以结构化运行日志为准。
- 未实现分布式任务锁；多实例部署时需要额外锁或只让一个实例启用定时刷新。
- 未实现交易日历、节假日停刷、指数退避或分级告警；按固定间隔和固定重试次数执行。
- 行情服务不可用时保留最近有效值和日期，不生成推测值；失败次数和错误显示在状态页。
- 定时刷新不绕过行情服务授权或凭据要求；当前基金 / 黄金参考源为公开接口，无凭据配置。
- 批量刷新没有请求回执；重复刷新只会在行情变化时生成一笔新观测，未变化时安全跳过。
