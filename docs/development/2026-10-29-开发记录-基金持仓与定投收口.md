# 2026-10-29 开发记录：基金持仓与定投收口

本轮来自一次以用户身份对基金持仓和定投模块的走查。目标只处理四个 P0 断点，不扩展新的资产类型，也不改收益口径。

## 1. 走查发现的问题

| 问题 | 影响 |
| --- | --- |
| 定投计划只能选已有持仓，未持有基金无法直接建立定投 | 新用户从零开始定投走不通 |
| 同一基金、类别、平台重复录入没有提示 | 持仓份额和成本会被静默翻倍 |
| 买入待确认只能等行情自动结转，没有手动确认入口 | 行情缺失或延迟时资金永久停在待确认 |
| 定投执行按扣款金额全额折算份额，申购费固定为 0 | A 类前端收费基金份额偏高、持有收益偏低 |

## 2. 本轮改动

### 2.1 定投直接建立计划

- 计划表单新增“搜索基金（未持有也可直接定投）”，复用基金搜索接口，选中后显示名称、代码、类别和确认周期。
- 保存时若该基金类别尚无持仓，先通过现有持仓录入接口建立一笔 0 份额、0 成本持仓，再保存计划；已存在时直接复用。
- 已持有基金仍可通过原下拉选择；两者互斥，切换时自动清空另一侧。
- 空状态提示从“请选择”改为“还没有基金持仓，可在下面搜索基金直接建立定投”。

### 2.2 重复持仓提示

- 录入已有持仓提交前，按“基金代码 + 份额类别 + 平台”检测重复；平台为空视为未标平台，可与任意平台命中。
- 命中后不直接写入，弹出对比：已有份额 / 成本与本次录入份额 / 成本。
- 提供三个动作：更新已有持仓、新增独立持仓、取消。
- 更新已有持仓调用份额核对接口，并新增可选成本参数，一次覆盖份额和成本；新增独立持仓沿用原录入接口。
- 平台下拉新增“未标平台”，与定投自动建立的 0 份额持仓保持一致。

### 2.3 买入确认手动兜底

- 补齐 `POST /api/ledger/funds/buys/{id}/confirm`，复用已有确认结转逻辑；此前 README 已列出该接口但控制器未暴露。
- 交易页“买入待确认”卡片新增“登记确认份额”，可填写确认份额、成交净值、净值日期、申购费、确认日期。
- 提供“按（扣款金额 − 申购费）÷ 净值 试算份额”，按四位小数向下取整，与后端自动确认口径一致。
- 确认申购费允许与待确认记录不同，但仍须大于等于 0 且小于扣款金额；成本始终按原扣款金额结转。

### 2.4 定投申购费

- `AutoPlan` 与 `PlanOccurrence` 增加 `fee` 字段，迁移 `20261029044040_AddPlanFee` 为两张表加 `numeric(18,2) not null default 0`。
- 期次生成时快照计划申购费，执行时传入买入待确认；自动确认份额按 `(扣款金额 − 申购费) ÷ T 日净值` 计算。
- 计划表单新增“每期申购费（元）”，要求小于每期金额、最多两位小数；非基金定投强制为 0。
- 备份文档同步包含计划与期次的申购费，旧备份缺少该字段时按 0 恢复。

## 3. 验证

- 后端 `291` 项通过、`18` 项真实 PostgreSQL 跳过，共 `309` 项；新增用例覆盖：确认费与待确认不同、份额核对同时更新成本、定投申购费随期次落库、申购费不小于金额时拒绝保存。
- 前端 `114` 项通过；新增用例覆盖：搜索新基金时先建 0 份额持仓再保存计划、重复持仓弹出并走更新路径、待确认买入手动登记份额和费用。
- 类型检查与生产构建通过。
- 独立临时库（`asset_keeper_review`，API 5070 / 前端 5174）完成浏览器验收：搜索基金直接建定投 → 立即执行生成含申购费的待确认 → 手动确认份额 → 重复录入弹出提示 → 更新已有持仓 → 新增独立持仓；结束后已停止服务并删除临时库。

## 4. 边界

- 未改平台字段的自由输入，仍只有直销 / 代销 / 未标平台三个选项；自定义平台留待后续。
- 重复持仓检测在前端完成，直接调用接口仍可新增独立持仓；后端未加强制唯一约束，避免影响同基金跨平台多笔持仓。
- 买入、赎回申请、赎回到账的业务日期仍固定为当天，本轮未开放补录；买入确认和赎回确认的净值日期已改为默认取 T 日。
- 定投申购费按每期固定金额记录，不按费率自动计算；实际费用不同时可在确认环节调整。
- 搜索新基金建计划时，若持仓已建立但计划保存失败，会留下 0 份额持仓；重试会复用该持仓，不重复创建。
