## 3. 本轮复核发现的实现缺口

以下为对照产品设计文档 V1.1 逐条核对的结果，均未在本轮修复，已记入迭代总览的“下一阶段与尚未实现范围”。

| 优先级 | 缺口 | 证据 |
| --- | --- | --- |
| 高 | 认证与访问控制完全缺失，控制器无 `[Authorize]`，全部 API 公开可写 | `api/src/AssetKeeper.Api/Program.cs` 仅有孤立的 `app.UseAuthorization()`；全仓无 `AddAuthentication` / `UseAuthentication` / `[Authorize]` |
| 高 | 计划待处理期次没有“补记本期”，只有“重新排队”和“跳过” | `web/src/views/PlanView.vue` 仅调用 `retryOccurrence` / `skipOccurrence`；`PlanOccurrenceStatus` 无用户补记状态 |
| 中 | 截图识别完全未实现，无页面、端点与草稿模型 | 仅剩未使用的 `LedgerEntrySource.Import` 枚举值 |
| 中 | 计划预览缺“总资产预计变化”“新增待确认投资”，前端未渲染公积金变化与行备注 | `PlanPreviewDto` 字段；`web/src/views/PlanView.vue` 预览区 |
| 中 | 投资展示设置不完整：无分组“胶囊 / 卡片”切换，指标缺“最近净值日收益”，排序未持久化 | `web/src/views/FundsView.vue` 指标选项与 `sortKey` |
| 低 | 账本明细缺“日期定位”；基金详情缺三个入口 | `web/src/views/LedgerView.vue`、`FundsView.vue` |
| 低 | 前端金额用 JS number 运算，与 3.3 节精确十进制要求不符（仅输入侧） | `web/src/utils/amount.ts` |

## 4. 后续建议

1. 先补认证与访问控制，再谈云端部署——当前全部 API 公开可写。
2. 补“补记本期”端点与界面入口，复用现有 `MutationExecutor` 防重与期次去重。
3. CI 增加 `postgres:16` service 容器，让 17 项数据库用例在 CI 中也跑起来。
4. 截图识别推迟到部署与认证之后单独立项，先确定识别服务商与图片传输范围。
5. 前端金额改用整数分或 decimal 库，消除输入侧的浮点误差。
