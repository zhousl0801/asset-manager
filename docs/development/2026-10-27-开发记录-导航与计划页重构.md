# 底部导航、计划分组与资产录入收口

日期：2026-10-27。范围：把底部导航调整为五项，计划页改为“交易日历 + 分组计划 + 执行记录”，简化积存金买卖与报价入口，把公积金每月缴存并入缴存/提取表单，并改为按资产录入状态自动判定总资产口径。

本轮承接同日的[会话 Cookie 与 Passkey 认证](2026-10-27-开发记录-会话Cookie认证.md)；认证部分不再重复记录。

## 1. 调整后的应用形态

底部主导航固定为 **总览 / 账本 / ＋记一笔 / 计划 / 我的** 五项，记一笔位于中央并作为独立页面打开。资产不再占用底部导航，首页头部也不再提供＋面板：

- 首页资产分布右上增加「管理 ›」，进入资产页维护余额和不持有标记；各类资产行仍进入现金、公积金、积存金和投资页。
- 首页“资产趋势”改为更简洁的标题和读数区，保留 7 日 / 1 月 / 3 月 / 全部范围、按日悬停读数和满 7 天才画曲线的规则，移除拖动提示和统计口径浮层。
- 计划页成为一级页面，首页和「我的」仍保留计划入口。

页面返回统一使用 `BackButton`：资产、账本、计划、公积金、积存金、备份、行情状态等页面不再各自维护“‹ 我的 / ‹ 总览”文案。

## 2. 计划页

### 2.1 交易日历

- 新增 `GET /api/ledger/plans/calendar?year=&month=`，返回指定月份每天的中国、美国、香港开市状态、来源和是否使用工作日回退。
- 新增 `PlanCalendar.vue`，按中国日期展示整月；中国休市日以浅色显示，美股 / 港股休市用“美 / 港”标记，并提示基金定投会顺延到下一个三地共同交易日。
- 支持前后月份切换、按月份缓存、加载失败重试和来源 / 覆盖范围展开；未维护年份显示“工作日回退”。
- 原计划页内的排期列表和按日期试算入口被移除，`POST /api/ledger/plans/preview` 与相关 DTO 一并删除。

### 2.2 分组计划

计划区按 **基金定投 / 公积金 / 定期收入** 三组展示，每组显示启用数量、金额汇总和暂停数量；空分组提供新建入口。公积金组内区分缴存与提取，标题随是否存在提取计划变化。

基金定投按基金名称合并为一张基金卡：同一基金的 A/C 等份额类别显示类别标签、各自金额、周期和下一期，合计金额只用于展示；展开后可分别编辑、暂停或恢复。`fundSip` 的唯一性和执行仍按“基金 + 类别 + 金额 + 周期 + 时间”逐条判断，合并只影响展示，不改变后台期次。

### 2.3 待处理与执行记录

- 待处理期次保留“补记本期 / 重新排队 / 跳过”三个动作；补记沿用原业务日期和金额。
- 执行记录继续按业务日期展示结果和错误信息。
- 计划页不再提供执行预览或试算现金入口；到期结果以待处理 / 失败期次为准。

## 3. 积存金

- 移除手动“更新报价”入口和 `updateGoldQuote` 前端调用；打开页面时若报价过期会自动请求刷新，失败保留最近有效值并显示陈旧状态。
- 卖出只填写克数和估值报价，到账金额按“克数 × 报价”计算并直接进入现金，不再选择“已到账 / 待到账”。后端仍兼容历史 `pendingArrival` 记录，通过到账接口登记。
- 买入和已有持仓核对使用当前有效报价；行情不可用时，买入按实际扣款 ÷ 克数估算，持仓核对要求先取得有效报价。
- 页面不再展示具体行情来源名称和已实现盈亏；已实现盈亏仍在后台核算。
- 买入、卖出不再提供关联现金核对差额入口；`BuyGoldRequest` 与 `SellGoldRequest` 移除 `relatedCashAdjustmentId`，基金买入同步移除该字段。

## 4. 资产与公积金

### 4.1 自动覆盖口径

资产覆盖不再需要用户手动确认“其他资产均已覆盖”。后端按以下条件自动计算 `coverageComplete`：

- 基金：已标记不持有，或已有基金持仓且估值可计算；
- 公积金：已标记不持有，或已有公积金账户；
- 积存金：已标记不持有，或有持仓且估值可计算；
- 现金始终计入。

四类资产都满足后，首页和资产页自动把“已记录资产”显示为“总资产”。仍有资产既未录入也未标记不持有则保持“已记录资产”。迁移 `20261027055828_RemoveAssetCoverageConfirmation` 删除原确认字段；`PUT /api/ledger/coverage` 只保留三个“不持有”标记。

资产页增加返回按钮和页头说明；「管理」入口仅出现在首页资产分布，资产页通过资产行继续进入各类详情。

### 4.2 公积金每月缴存

公积金页主操作改为 **录入余额 / 缴存·提取**。缴存与提取可在同一表单中只填一项或同时登记；提取仍可关联漏记现金核对。

“每月自动缴存”并入缴存/提取表单：勾选后填写每月金额、日期和时间，可新建、更新、暂停、恢复已有 `providentDeposit` 计划；表单显示当前计划的金额和启用状态。每月提取仍是独立计划，继续在计划页管理。

## 5. 数据与接口变化

| 项目 | 变化 |
| --- | --- |
| `GET /api/ledger/plans` | 概览不再返回 `calendarDays`，交易日历改由独立端点按月份读取 |
| `GET /api/ledger/plans/calendar` | 新增；返回 `year`、`month`、`days` |
| `POST /api/ledger/plans/preview` | 删除，连同 `PlanPreviewRequest` / `PlanPreviewDto` 与前端类型 |
| `POST /api/ledger/gold/sells` | 请求不再接受 `settlement`，服务端按默认直接到账处理；历史待到账记录仍可到账 |
| `POST /api/ledger/gold/buys`、`/holding` | 请求移除 `relatedCashAdjustmentId`；前端不再展示手动报价 |
| `POST /api/ledger/funds/buys` | 请求移除 `relatedCashAdjustmentId` |
| 数据库 | 第 16 个迁移 `RemoveAssetCoverageConfirmation` 删除覆盖确认列 |

积存金提供方仍使用工商银行积存金主动积存价，但页面和普通日志统一称“积存金报价”，不再把来源名称暴露为页面文案。

## 7. 已知边界

- 积存金旧待到账记录继续保留到账接口，但页面不再新建待到账卖出；历史数据不会因入口移除而被改写。
- 计划页的基金合并只按基金名称归集展示；名称相同但实际不是同一基金的异常数据仍会合并，需依赖基金代码和类别核对。
- 交易日历依赖本地维护的三市场年度数据；未维护年份按周一至周五回退，临时休市仍需人工核对。
- 手动积存金报价接口仍保留在服务端用于维护 / 兼容，但页面不提供入口；后续若完全废弃需单独迁移历史报价来源。
- 总资产自动判定以“已录入且估值可计算”为准；基金或积存金因行情 / 起始依据不足无法估值时，仍显示“已记录资产”。
- 当前仍按单实例运行；计划执行、行情刷新和 Passkey 挑战缓存均为进程内状态。
