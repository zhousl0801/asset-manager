# 2026-10-30 开发记录：基金累计收益与建账前已实现收益

## 1. 现象

基金页「组合持仓」打开「累计收益」列后，六只基金的累计收益与持有收益完全一样：

| 基金 | 持有收益 | 累计收益（修复前） |
| --- | --- | --- |
| 浦银 014002 | +5,635.83 | +5,635.83 |
| 长城 018036 | −4,990.50 | −4,990.50 |
| 银华 016702 | −542.60 | −542.60 |
| 建信 018147 | −746.00 | −746.00 |
| 华夏 002891 | −2,555.49 | −2,555.49 |
| 国富 006373 | −592.98 | −592.98 |

## 2. 原因

显示口径没错：`累计收益 = 持有收益 + 已实现收益`，而账本从 2026-10-29 建账，只录了持仓快照，没有任何卖出记录，已实现收益为 0，所以两列必然相同。

问题在语义：支付宝的「累计收益」是**从买入这只基金起**的总盈亏，包含建账前已经发生的卖出与分红。持仓快照只能还原当前份额和成本，还原不了这段历史，所以 APP 算出的「累计」其实只是「建账以来」，数字看着像 bug。

## 3. 修改

**后端**

- `FundPosition` 新增 `PriorRealizedProfit`（建账前已实现收益，`prior_realized_profit` 列，迁移 `20261030094713_AddFundPriorRealizedProfit`），由用户按平台数字录入，重放不会覆盖。
- 新增 `TotalRealizedProfit => RealizedProfit + PriorRealizedProfit`；`FundService` 的持仓、类别、基金汇总和总览「已实现收益」全部改用它，所以 `累计 = 持有 + 已实现` 自然成立，前端算式不用改。
- 新接口 `POST /api/ledger/funds/positions/{positionId}/prior-realized-profit`，走幂等执行器；金额正负皆可、最多两位小数，不改份额、成本与现金。
- 录入持仓 `CreateFundPositionRequest` 增加可选 `PriorRealizedProfit`，首次录入就能带上。
- 备份文档 `BackupFundPosition` 增加该字段；旧备份缺字段时按 0 还原。

**前端**

- 基金详情里每个平台持仓增加一行「建账前已实现 +¥2,762.09 修改」，点开弹层按平台数字填写，说明写明「按平台上的累计收益 − 持有收益填写」。
- 类型与 API 客户端同步；新增 `parseSignedAmount`（允许负号，最多两位小数）。

**数据补录**

按 2026-10-30 的支付宝截图逐只计算 `累计收益 − 持有收益`：

| 基金 | 支付宝累计 | 支付宝持有 | 建账前已实现 |

补录后基金页：已实现收益 +2,997.07，累计收益逐只与支付宝对得上（累计 = 建账前已实现 + 当次净值变动后的持有收益）：

- 浦银 +5,635.83 + 2,762.09 = **+8,397.92**
- 长城 −4,990.50 − 63.13 = **−5,053.63**（支付宝 −4,045.38 对应的持有收益还是 −3,982.25，净值由 2.4473 跌到 2.3928 后又扩大 1,008.25）
- 银华 −542.60 + 256.17 = **−286.43**
- 建信 −746.00 = **−746.00**
- 华夏 −2,555.49 + 41.78 = **−2,513.71**
- 国富 −592.98 + 0.16 = **−592.82**

组合合计：持有 −3,791.74 + 已实现 +2,997.07 = 累计 **−794.67**。

## 5. 遗留

- 该字段只影响收益展示，不参与成本、份额、现金、总资产和趋势计算。
- 以后从平台换到新账本、或某只基金又发生了卖出时，按支付宝的新差量重新填一次即可；账本内产生的已实现收益由重放自动累加，不需要手填。
