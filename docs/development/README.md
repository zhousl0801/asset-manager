## 2. 功能如何演进到当前实现

| 功能 | 首轮实现 | G0 收口 | G1 当前实现 |
| --- | --- | --- | --- |
| 单账本与并发 | 初始化和账户 / 持仓版本保护 | 数据库单例约束，核对显式版本，纯日期更正也参加保护 | 增加账本统一版本，历史预览与跨资产写入参加同一并发保护 |
| 请求重试 | 请求 ID 防重复写入 | 操作类型、规范化请求内容与首次结果持久化；浏览器可查询 / 重试原请求 | 历史确认同样接入回执恢复；预览绑定确切内容和账本版本，旧响应不能恢复失效确认 |
| 现金核对 | 独立差额，不计生活收支 | 防止旧请求覆盖新余额；拦截核对之前的不安全变动 | 保存当时目标余额，历史重放重算差额；找到漏记业务后可关联替换差额，不重复扣款 |
| 资产起始日期 | 已有持仓录入，独立日期能力未齐 | 保留阶段限制，不声明完整历史能力 | 现金余额日期、基金 / 黄金持仓日期与行情日期分开；公积金起始余额独立记录且不计缴存 / 收入 |
| 历史买卖和成本 | 直接修改当前份额、克数、成本与收益 | 对不能可靠重算的补录先拒绝，避免静默错账 | 按业务日期和保存的顺序重放，校验每一时点余额 / 数量，重算后续成本与已实现收益 |
| 行情与估值 | 手动维护当前净值 / 报价 | 旧日期不覆盖当前最新行情 | 保存有效日、来源、取得时刻及修订；来源可更正 / 撤销，过去日期不使用未来行情 |
| 查询与回看 | 当前余额、资产总览和周期明细 | 完整范围聚合与独立分页，部分日明细明确标小计 | 增加历史事实及指定日资产回看；依据不足时不声明完整总资产 |
| 审计和迁移 | 资产交易留痕；前 5 个迁移 | 回执保存原状态；第 6 个迁移增加单例约束及回执表 | 更正原因与原事实 / 行情快照留存；第 7 个迁移增加重放与行情模型，旧持仓日期待确认 |

G0 的 `HistorySafety` 拒绝策略已由 G1 的事实重放替代；G0 文档中的“完整历史重算属于下一步”只描述当时阶段，不是当前待办。同样，首轮文档中的初始请求规则、迁移数量和验证数量应按 G0、G1、G2 的后续变化理解。

G2 在 G1 基础上把基金买入拆成“待确认”和“确认”两个业务事实：扣款时现金减少、待确认增加，持仓不变；确认时待确认结转份额与成本，不再扣现金。现金、待确认和已确认持仓互斥计入，历史重放按各自业务日期和顺序处理，已确认的待确认记录不能直接改金额或撤销。

## 3. 已关闭的 Review 问题

| 轮次 | 关闭的问题 |
| --- | --- |
| G0 主修复 | 并发初始化产生多个账本；旧核对请求覆盖后续余额；历史补录成本错误；旧行情覆盖最新估值；同 ID 改内容仍假成功；明细截断导致汇总少算；公积金列表月份与余额日期混用 |
| G0 最终审查 | 纯日期更正缺少现金并发保护；公积金历史提取绕过现金核对边界；分页日期标题显示不完整合计而未说明 |
| G1 最终审查 | 手工更正业务顺序未推进自动分配器；迁移缓存行情未关联可更正的来源事实；预览期间编辑草稿后旧响应仍可确认；报价预览未展示价格、有效日、估值和总资产变化 |

G1 的报价预览缺项在审查中最初列为 Minor；考虑到用户需要看到主要估值影响后才能确认，本轮将其提升为必修并完成回归。各轮修复前失败、修复后通过的证据及具体验收路径保留在阶段记录中。
