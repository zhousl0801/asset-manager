# 2026-10-22 开发记录：自动记账计划与后台任务

## 1. 已实现行为

### 四类计划

| 类型 | 执行结果 |
| --- | --- |
| 工资到账 | 现金增加，生成“工资”分类收入 |
| 公积金缴存 | 公积金增加，不改变现金和工资收入 |
| 公积金提取 | 公积金减少，现金等额增加；余额不足整笔待处理 |
| 基金定投 | 现金减少，生成基金买入待确认；现金不足整笔待处理 |

- 工资、缴存、提取各维护一条主计划；基金定投可以有多条，相同基金、金额和周期会提示核对重复。
- 支持每月或每周周期；每月 31 日遇短月按当月最后一天执行。
- 计划开始日期不得早于账本起始日期；保存或修改只影响后续期次，不立即生成历史记录。
- 暂停保留已有期次，暂停期间不补生成；恢复从下一期继续。

### 执行期次与状态

- 每个计划每个周期生成唯一执行期次，保存应执行业务日期、计划版本、金额快照、基金持仓快照和结果。
- 期次状态包括：待执行、已记账、待处理、执行失败、已跳过。
- 已记账期次保留关联的收支、公积金或基金交易标识；修改计划不会改动已有期次的金额快照。
- 同日执行顺序固定为工资 → 缴存 → 提取 → 定投；同类型按计划创建顺序。
- 余额或资料不足进入待处理，不部分扣款、不阻断其他计划；用户可重新排队或跳过本期。
- 同一期使用期次标识作为业务 `requestId`，重试或进程恢复不会产生第二笔流水。

### 后台任务与预览

- 新增 `PlanSchedulerService` 后台服务，默认每 60 秒检查一次到期计划，不依赖浏览器。
- 后台运行使用进程内互斥；期次表对“计划 + 周期”建立唯一索引，重复运行不会重复生成。
- 服务短暂中断后，按原业务日期补齐尚未生成的期次，再按顺序处理。
- 计划页提供按日试算：可输入日期和试算现金，展示执行顺序、预计变动、已记账 / 已跳过 / 待处理以及余额不足；试算不写账本、不占用期次。
- 计划页展示启用数量、下一期、计划列表、待处理期次和最近执行记录；首页提供“自动记账与执行记录”入口。

## 2. 接口与数据变化

| 接口 | 说明 |
| --- | --- |
| `GET /api/ledger/plans` | 计划、待处理期次、执行记录、现金与公积金余额 |
| `POST /api/ledger/plans` | 新建或编辑计划；使用 `requestId` 幂等和 `expectedVersion` 并发保护 |
| `POST /api/ledger/plans/{id}/pause` | 暂停计划 |
| `POST /api/ledger/plans/{id}/resume` | 恢复计划，从下一期继续 |
| `POST /api/ledger/plans/occurrences/{id}/retry` | 重新排队待处理 / 失败期次 |
| `POST /api/ledger/plans/occurrences/{id}/skip` | 跳过本期 |
| `POST /api/ledger/plans/preview` | 按日期和试算现金只读试算 |
| `POST /api/ledger/plans/run` | 手动触发一次到期执行 |

第 10 个迁移 `AddAutoPlans` 新增 `auto_plans` 和 `plan_occurrences` 表；期次表对 `plan_id + period_key` 唯一，并记录计划快照、状态、错误和关联记录。

配置：

```text
PlanScheduler:Enabled         默认 true
PlanScheduler:IntervalSeconds 默认 60
```

测试与本地自动化场景可将 `PlanScheduler:Enabled` 设为 `false`；浏览器验收使用 5 秒间隔验证后台自动执行。

## 4. 边界

- 后台任务使用单进程互斥和数据库唯一索引；当前未实现多实例分布式锁，部署多副本时需要补充租约或数据库锁。
- 待处理和失败期次不会静默自动重试，需要用户重新排队；重新排队后由后台任务或“立即执行”处理。
- 关联业务被历史更正 / 撤销后，期次当前仍显示“已记账”，尚未自动标记为“已更正 / 已撤销”；期次占位和去重仍保留。
- 预览只试算所选日期，不纳入中间日期的其他收支、行情变化或自动计划。
- 计划只生成账本记录，不验证银行或平台实际资金操作。
- 真实 iPhone、跨浏览器、读屏和 PWA 安装 / 升级验收仍未执行。
