# 2026-10-30 开发记录：积存金空账本无法录入持仓

## 1. 现象

新账本（清库后重新初始化，起始日 2026-10-30）进入积存金页，报价已经自动刷新成功（854.65 元/克，日期当天），但页面仍显示「行情待补」；点「录入 / 核对持仓」填写克数和成本后，保存被前端拦下，提示「行情暂不可用，请稍后自动获取报价后再保存。」

`GET /api/ledger/gold` 当时返回：

```json
{ "quote": 854.65, "quoteDate": "2026-10-30", "hasEffectiveQuote": false, "isConfigured": true, "grams": 0 }
```

即「报价存在但被判定为无有效报价」。

## 2. 原因

`LedgerReplayCalculator` 计算积存金重放结果时，把「能否给出价格」和「持仓是否有历史依据」绑在一起：

```csharp
value: (unknownGold ? asOfDate != currentDate : goldState.CoverageFrom is null) ? null : quote?.Price
```

`goldState.CoverageFrom` 只在出现第一条起始、核对或买入事实时才有值。账本刚建立、还没录入任何积存金记录时，`CoverageFrom` 必然是 null，于是价格被直接置空 → `GoldService` 的 `HasEffectiveQuote = replay.Gold?.Value is not null` 为 false → 页面显示「行情待补」，前端保存前又要求 `hasEffectiveQuote` 为真，形成死锁：不录入就没有历史依据，没有历史依据就不允许录入。

积存金是唯一会出现这种状态的资产：报价刷新会落库一条 `gold_holdings` 快照（克数 0、报价与日期有值），基金和股票持仓只在录入或买入时才创建，必然自带事实。

## 3. 修改

`LedgerReplayCalculator` 积存金价格只在「持仓需要人工确认日期且在看历史日期」时置空，其余情况只要存在有效观测就用该价格：

```csharp
// 还没有任何积存金持仓记录时，快照克数（通常为 0）即为准绳，报价仍可用于估值和录入首笔持仓。
(unknownGold && asOfDate != currentDate) ? null : quote?.Price
```

持仓数量口径不变：没有历史事实时仍取快照克数；`historyConfirmed`（`CanRebuild`）与资产覆盖判定也不变，空账本仍算「积存金依据不足」，首页继续显示「已记录资产」而不是「总资产」。

## 4. 验证

- 新增用例 `GetOverviewAsync_WithQuoteButNoHoldingFacts_UsesQuoteForValuation`：空账本 + 只有报价快照时 `hasEffectiveQuote` 为真、报价与日期取快照值、估值为 0
- 新增用例 `GetOverviewAsync_WithoutAnyQuote_ReportsMissingQuote`：连报价观测都没有时仍判为无有效报价，前端继续拦住保存
- 后端 338 项（320 通过 + 18 项真实 PostgreSQL 跳过）
- 临时库 `asset_keeper_gold_check` 端到端：初始化账本 → `POST /api/ledger/gold/quote/refresh` 返回 854.90 元/克 → `hasEffectiveQuote` 为真 → `POST /api/ledger/gold/holding` 录入 12.4948 克、成本 922.62 → 返回估值 10,681.80、平均成本 73.84 元/克 → 总资产 217,406.80（覆盖仍为 false，因为基金、股票、公积金未录入）。验证后临时库已删除
- 真实实例（5069）重新构建后端后：页面显示「¥0.00」「持仓估值 0.0000 克 × 854.87 元/克」「估值报价 ¥854.87 / 克 2026年10月30日 · 自动获取」，录入弹层不再出现行情拦截提示

## 5. 边界

- 只修「有报价但被判为无报价」这一种空账本状态；真正拿不到报价时（请求失败、返回无效价格）仍然拦截保存，要求先刷新行情
- 录入时不会校验「成本 ÷ 克数」与当前报价是否偏离，成本填错（例如漏一位）仍会原样保存，需录入时自己核对平均成本
