# 2026-10-22 开发记录：G2 基金买入待确认

本轮承接 G1 业务事实与历史重放，实现 G2 的第一个切片：基金买入先记待确认，再按实际份额、净值和费用确认转入持仓。赎回待到账与积存金卖出待到账仍未实现。

## 1. 已实现行为

### 买入待确认

- `POST /api/ledger/funds/buys` 只接收基金持仓、实际扣款金额、业务日期、备注和 `requestId`，不再接收份额与成交净值。
- 保存后现金减少、买入待确认等额增加，持仓份额与成本不变；基金资产合计仍包含这笔待确认金额，总资产不因买入或确认而重复计算。
- 待确认记录支持更正金额 / 日期、撤销；撤销后现金恢复。现金页将这笔扣款标为“基金买入待确认”，不计入生活收支。

### 确认转入持仓

- 新增 `POST /api/ledger/funds/buys/{transactionId}/confirm`，录入确认份额、成交净值、净值日期、费用、确认日期和备注。
- 确认沿用原扣款金额，不再扣减现金；待确认金额转为份额与成本，费用从已扣款金额中列示，成交价差体现在持有收益中。
- 同一笔待确认只能确认一次；确认日期不得早于买入日期，净值日期不得晚于确认日期；费用必须在 0 与扣款金额之间。
- 确认、待确认都使用 `requestId` 幂等；重复提交返回首次结果，不重复扣款或加仓。

### 历史重放与更正

- 待确认和确认都是独立业务事实，按业务日期和同日顺序重放：待确认计入在途金额，确认当日结转份额与成本。
- 已确认的待确认记录不能直接更正金额或撤销，需先撤销确认；确认金额由对应待确认记录决定，不能单独改数。
- 撤销确认后记录回到待确认状态，现金保持不变；若后续卖出因此超卖，历史预览会拒绝。
- 历史页展示每笔基金的待确认金额、确认费用和关联事实；影响预览增加待确认金额对比。
- 行情仍按有效日期取最近记录；确认时录入的成交净值作为该有效日的行情来源，可随确认事实更正或撤销。

## 2. 数据与接口变化

| 项目 | 变化 |
| --- | --- |
| `asset_transactions` | 新增 `linked_transaction_id`（确认指向待确认）和 `fee`（确认费用，默认 0）；新增账本内关联索引 |
| `AssetTransactionKind` | 新增 `FundBuyPending`、`FundBuyConfirm`；历史 `FundBuy` 保留为既有已成交记录 |
| `GET /api/ledger/funds` | 返回 `pendingAmount`、`pendingBuys`；`totalValue` 包含待确认金额 |
| `POST /api/ledger/funds/buys` | 请求改为 `positionId/amount/businessDate/note/requestId/relatedCashAdjustmentId` |
| `POST /api/ledger/funds/buys/{id}/confirm` | 新增确认接口，请求为 `shares/netValue/netValueDate/fee/businessDate/note/requestId` |
| 历史接口 | 资产事实可携带 `fee`；待确认和确认进入同一重放与预览 |
| 首页 / 现金页 | 基金金额包含待确认；现金流水标题区分“基金买入待确认” |

第 8 个迁移为 `20261022035034_AddFundBuyPending`，为既有 `asset_transactions` 增加列和索引，不重写历史记录；旧记录按已成交处理，费用为 0。
