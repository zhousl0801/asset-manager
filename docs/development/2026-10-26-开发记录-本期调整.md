## 修改结果

- 积存金自动参考价使用工商银行积存金主动积存价。当前服务端行情提供方和页面已接工行；修正文档中仍写作上期所参考价的说明，手动报价入口保留。
- 计划待处理期次新增“补记本期”按钮，调用既有期次补记接口，沿用原业务日期、金额和期次幂等标识。
- 计划执行使用进程内 `SemaphoreSlim`；行情刷新状态监控使用单例进程内锁。当前应用按单实例运行，不引入分布式锁。
- 基金活动列表过滤 `quote` 事件，不把自动净值更新显示成交易；净值只通过数据源刷新，保留可追溯的行情事实。
- 前端金额与数量格式化、输入解析和汇总运算使用 Decimal.js；HTTP JSON 输入输出保持既有数值格式。

## 基金申购确认与持仓快捷操作

- 新增持仓必须填写基金代码，初始净值从基金数据源读取；原有请求中的手工净值字段忽略且不暴露在 JSON 接口中。净值手工更新 API 已移除，列表提供按持仓刷新的数据源入口。
- 持仓详情的平台记录新增买入、赎回、份额调整和刷新净值快捷操作。份额调整写入当天的 `FundCorrection` 核对事实，沿用原持仓成本；份额归零时成本同步归零。
- 申购记录保存实际扣款、申购费、确认周期、实际下单日与基金 T 日。北京时间 15:00 前可撤销，15:00 整起不可撤销；15:00 后的当日申购将 T 日移到下一开放交易日，但现金仍按下单日入账。
- 持仓默认 T+2，可在新增持仓时设为 T+1。到达确认日后，行情刷新从东财历史净值中取精确 T 日净值，按 `(扣款 - 申购费) / 净值` 向下保留四位份额并自动结转；若历史净值尚未披露，则保持待确认并在后续刷新中重试。
- 赎回申请保留手工登记实际确认结果与到账结果；15:00 前可以撤销申请，之后锁定。撤销使用账本历史重放恢复现金或解冻份额，流水仍标记为已撤销以保留审计记录。
