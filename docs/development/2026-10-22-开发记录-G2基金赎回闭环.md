## 1. 已实现行为

### 申请赎回

- `POST /api/ledger/funds/sells` 改为提交基金持仓、申请份额、申请日期和备注，不再直接录入净回款。
- 申请时份额仍留在已确认持仓中估值，同时标记为冻结；可售份额为持有份额减去已申请未确认份额。
- 重复申请、超过可售份额或历史时点持有不足都会被拒绝；申请本身不改变现金和持仓成本。

### 确认赎回

- 新增 `POST /api/ledger/funds/sells/{transactionId}/confirm`，录入确认份额、成交净值、净值日期、费用、净到账金额、确认日期和备注。
- 确认份额不能超过申请份额，允许少于申请份额；申请在确认后关闭，剩余冻结份额自动释放。
- 确认时按比例结转成本、减少持仓份额，并把净到账金额计入赎回待到账；差额计入已实现收益，现金不变。
- 同一笔申请只能确认一次；确认日期不得早于申请日期，净值日期不得晚于确认日期。

### 赎回到账

- 新增 `POST /api/ledger/funds/sells/{transactionId}/arrival`，录入到账金额、到账日期和备注。
- 到账金额必须与待到账金额一致，才能从待到账转入现金；不一致时要求先更正赎回确认，不静默抹平差额。
- 同一笔确认只能到账一次；到账日期不得早于确认日期。到账只做资产状态转移，不再次确认收益，也不计入生活收入。

### 历史重放与更正

- 申请、确认、到账都是独立业务事实，按业务日期和同日顺序重放。持仓估值仍包含已申请份额；基金资产另加待确认买入和赎回待到账。
- 已确认的申请不能直接更正份额或撤销，需先撤销确认；已到账的确认不能撤销，需先撤销到账。
- 撤销确认会恢复持仓份额与成本、冲回已实现收益和待到账；撤销到账会恢复待到账并减少现金。
- 到账金额在历史更正时必须等于确认金额；确认金额变化后，到账记录需先撤销再重新登记。
- 首页、基金页、历史页和现金页分别展示待确认买入、已申请赎回、赎回待到账与到账流水。

## 2. 接口与数据变化

| 项目 | 变化 |
| --- | --- |
| `AssetTransactionKind` | 新增 `FundSellApply`、`FundSellConfirm`、`FundSellArrival`；历史 `FundSell` 保留为既有直接成交记录 |
| `POST /api/ledger/funds/sells` | 请求改为 `positionId/shares/businessDate/note/requestId`，只登记申请 |
| `POST /api/ledger/funds/sells/{id}/confirm` | 新增确认接口，请求为 `shares/netValue/netValueDate/fee/netAmount/businessDate/note/requestId` |
| `POST /api/ledger/funds/sells/{id}/arrival` | 新增到账接口，请求为 `amount/businessDate/note/requestId` |
| `GET /api/ledger/funds` | 返回 `pendingArrivalAmount`、`sellApplications`、`pendingArrivals`；`totalValue` 包含待到账 |
| 历史接口 | 赎回申请 / 确认 / 到账进入同一重放与预览；确认费用可参与更正 |
| 首页 / 现金页 | 基金金额包含待到账；到账流水标为“基金赎回到账” |

本轮复用第 8 个迁移新增的 `linked_transaction_id` 和 `fee` 字段，没有新增数据库迁移。申请、确认、到账之间通过 `linked_transaction_id` 串联。
