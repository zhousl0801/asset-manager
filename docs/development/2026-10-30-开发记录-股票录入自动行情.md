# 2026-10-30 开发记录：股票录入持仓的现价与日期

## 1. 现象

在股票页「录入已有持仓」（`159915 创业板ETF易方达`、10000 股、成本 2.772、现价 2.435、行情日期 2026-10-30、持仓日期 2026-10-27）点保存，界面没有任何成功反馈。同时提出：现价不应该手填，直接取最新行情。

复现同样的请求：

```json
POST /api/ledger/stocks/positions
{"market":"shenzhen","code":"159915","shares":10000,"cost":2.772,"price":2.435,
 "priceDate":"2026-10-30","holdingDate":"2026-10-27",...}

HTTP/1.1 400
{"errors":{"":["业务日期不能早于账本起始日期。"]}}
```

## 2. 原因

三个独立问题叠在一起：

1. **持仓日期早于账本起始日**：当天把账本起始日改成了 2026-10-30，弹出的默认日期也是今天，但填了 2026-10-27。`AssetValidation.ValidateBusinessDate` 拒绝早于起始日的业务日期。起始持仓本质是「起始日的持仓快照」，不是买入日期。
2. **现价与行情日期要手填**：录入只用它们给持仓定初始估值，实际应该直接取最新行情，手填既多余又容易和真实报价不一致。
3. **成本单位错位**：字段写「持仓成本（元）」，券商 App 显示的是每股成本，填 2.772 会被当成总成本 2.772 元，1 万股的平均成本变成 0.0003 元。

## 3. 修改

后端：

- 新增 `GET /api/ledger/stocks/quote?market=&code=`，由 `StockService.GetQuoteAsync` 调行情 provider 取最新价，返回市场、代码、现价、行情日期、昨收和来源；只读，不写行情观测、不建持仓
- 行情不可用统一返回 502，文案与其它行情失败一致

前端（股票页「录入股票持仓」）：

- 去掉「现价」和「行情日期」两个输入，改成只读行情行：选中股票后自动取最新价（例如 `2.44 元 · 2026年10月30日`），失败时说明原因并提供「重新获取」
- 买入弹层的成交价仍可编辑，但默认带出最新价，并按实际成交价改写
- 「持仓成本（元）」改为「成本均价（元 / 股）」，保存时按「股数 × 均价」折算总额，表单内实时显示持仓成本合计
- 新增单价解析 `parseUnitPrice`（允许 0 与最多 4 位小数），股票与积存金的成本均价共用
- 持仓日期加下限（账本起始日）与上限（今天），并注明「起始持仓是当天快照，不能早于账本起始日 X，通常直接填今天」
- 页面挂载时读取一次账本 `startDate`，失败则不加下限，不影响其它操作

## 4. 验证

- 后端 340 项（322 通过 + 18 项真实 PostgreSQL 跳过）：新增 `GetQuoteAsync_ReturnsLatestPriceWithoutWritingAnything`（代码首尾空格被归一化、不写任何资产流水）与 `GetQuoteAsync_WithoutProvider_ReportsUnavailable`
- 前端 141 项通过，`vue-tsc` 与生产构建通过；新增用例覆盖「选股后自动取最新价、弹层不再有手填现价与行情日期、成本均价折算为 ¥27,720.00、提交 `cost: 27720`」
- 真实实例：`GET /api/ledger/stocks/quote?market=shenzhen&code=159915` 返回 `price 2.435`、`priceDate 2026-10-30`、`previousClose 2.535`；浏览器核对弹层字段与自动现价

## 5. 边界

- 行情接口只做估值参考；实际成交仍以买入 / 卖出表单里填写的成交价为准
- 起始持仓仍受账本起始日约束：账本起始日改成今天后，任何早于今天的持仓日期都会被拒绝，这属于覆盖口径而非 bug；需要补录更早的历史，要把起始日往前调
- 自动取价失败时不回退到旧报价，只提示失败并允许重试，避免把过期价格当成今日估值
