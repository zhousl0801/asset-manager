# 基金交易日历与持仓聚合设计规格

日期：2026-10-26  
状态：已实施；逐项金额经用户于 2026-10-26 确认  
范围：资产管家基金持仓视图、基金定投计划和计划排期

## 1. 目标和已确认需求

1. 所有基金持仓在持仓页不再按直销、代销等平台渠道拆行，按基金汇总展示。
2. 基金详情按份额类别（如 A、C）分开展示金额、份额、成本和盈亏；不展示渠道分组。
3. 底层原始持仓和交易来源保留，供核对与历史追溯；展示层聚合，不通过删除原始记录实现合并。
4. 新增基金定投“交易日”周期。此处交易日要求中国、美国、香港三地同一日历日期都开市；任一已知休市则跳过。半日市视为开市。
5. 如果某市场的目标年度官方日历还未维护，该市场暂按周一至周五判断；另外已维护的市场仍遵循其官方休市安排。以后补入官方日历，只影响未来期次，不自动撤销或改写历史期次。
6. 建立以下 8 条计划，计划开始日为创建时之后的下一个合格交易日：

## 2. 市场日历

### 2.1 判断规则

- 计划日期以资产管家 `Asia/Shanghai` 账本日期为准。
- 三地按计划日期对应的各自本地日历日期查询；统一比较同一个 `yyyy-MM-dd` 日期，不按 UTC 日期换算。
- 某日为周末时不执行。
- 对已维护年份，读取中国、美国和香港市场各自的年度开市/休市日期；只有三个市场均开市时，才产生定投期次。
- 对未维护年份的市场，临时使用周一至周五作为开市日。系统应在计划界面标出该市场处于“工作日回退”状态。
- 官方日历补齐后，仅对当前日期之后的计划日期使用更新后的日历；已记账期次、待确认买入和历史记录不自动撤销或重算。
- 计划执行仍使用当前系统的唯一期次键和幂等约束，避免后台重试重复创建买入记录。

### 2.2 数据来源和更新

日历以本地版本化数据维护，运行时不依赖外网。按年度记录来源链接、覆盖年份、发布日期和休市日期；官方日历发布后更新对应数据文件。

- 中国：上交所 / 深交所官方休市安排。
- 美国：Nasdaq 官方美国股票市场节假日安排。
- 香港：HKEX 官方证券市场假期通告。

参考来源：

- [上交所休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/)
- [Nasdaq U.S. Market Holidays](https://www.nasdaq.com/market-activity/stock-market-holiday-schedule)
- [HKEX 市场假期通告与日历](https://www.hkex.com.hk/Global/HKEX-Market-Search-Result?mode=basic&q=0001&s=796&sc_lang=en&u=Market+Data%7CProducts%7CServices%7CListing%7CNews%7CFAQ%7CGlobal&v=LastModifiedTime)

此逻辑只判定市场是否休市，不判断某只 QDII 基金或销售平台是否另行暂停申购；这些业务公告不自动纳入日历。

## 3. 持仓聚合

### 3.1 展示层

- 持仓列表按基金身份汇总，不因渠道不同显示重复基金行。
- 同一基金的全部类别合并显示基金总金额和总盈亏。
- 详情按份额类别展示；同一类别下的不同渠道持仓汇总份额、金额、成本、持有盈亏和已实现盈亏，不显示渠道拆分。
- 若基金类别缺失，作为单独的“未标类别”行展示，不与已知类别混合。
- 汇总金额、成本、盈亏采用底层持仓逐项求和，金额保留两位小数；份额按同一基金、同一类别求和，保留四位小数。净值不做加总。
- 有代码时以基金代码和类别识别同一份额类别；无代码时使用规范化基金名称和类别，并在详情中提示身份匹配依据。
- 搜索、排序、分组筛选和组合指标均使用聚合后的结果，不能将底层多渠道行重复计入总额。

### 3.2 数据保留与计划绑定

- 现有按平台保存的原始持仓行继续作为内部来源记录，不删除、不把历史活动改写到另一渠道。
- 定投计划以基金代码/名称及份额类别为业务目标，而不是要求用户选择直销或代销持仓。
- 计划执行生成的买入活动并入相同基金类别的聚合结果；渠道字段由系统内部管理，不作为用户需要区分的计划配置。
- 同一基金类别只允许存在一条相同金额、周期及时间的有效定投计划；重复保存返回冲突，不产生重复计划。

## 4. 定投执行语义

- 保存计划不会立即扣款，也不会向基金销售平台下单。
- 每个到期交易日，后台计划服务会在资产管家账本生成基金待确认买入记录并扣减账本现金；用户仍需在基金交易确认后核对实际份额和净值。
- 计划的交易日列表、下一期日期、预览和后台执行必须共用同一日历判断服务，避免界面与后台口径不一致。
- 计划开始日取创建后的下一个中国、美国、香港均开市日期，不补做创建当天的计划。

## 5. 实施范围与验证

实现需要覆盖：

1. 后端日历数据、跨市场开市判断及按交易日生成期次。
2. 定投计划保存、重复校验、下一期和预览接口的交易日支持。
3. 持仓按基金及份额类别聚合的查询模型，以及前端列表、详情、搜索、排序和分组汇总。
4. 定投计划按聚合基金类别选择、执行与买入活动归属。
5. 官方日历数据来源/覆盖状态提示和缺失年份回退提示。
6. 对周末、三地分别休市、仅单一市场休市、半日市、缺失年份回退、日历更新后的未来日期、幂等重试和聚合金额/盈亏进行自动化验证。

完成后再检查现有持仓总额是否因聚合视图发生变化（总金额应保持不变），核对大成 C 两个平台来源相加后的份额与成本，并回读 8 条计划。创建计划时只写入资产管家本地账本，不执行真实基金订单。

## 6. 明确不在本规格内

- 通过券商或基金销售平台 API 执行真实申购。
- 自动抓取或解释基金公司的临时暂停申购公告。
- 擅自合并、删除或改写历史原始平台持仓及历史活动。
- 将同一基金不同份额类别（A/C/I 等）合并为一个成本或盈亏数字。
